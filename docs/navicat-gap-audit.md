## 本轮修复与回归场景

| 问题 | 触发与影响 | 修复 |
|---|---|---|
| SQLite 导出覆盖源库 | 保存路径选中正在导出的数据库；结构导出直接写入 SQL，数据导出先删除源文件。 | 拒绝源库、路径别名和日志文件；先生成临时备份，完整成功后替换。 |
| SQLite 导出失败丢失旧备份 | 原备份先删除，随后 VACUUM 失败。 | 临时文件暂存，失败保留旧备份并清理临时文件。 |
| SQLite 恢复接受损坏备份 | 文件保留 16 字节 magic，但内容被截断或损坏，也会覆盖好库。 | 暂存后只读打开并执行 quick_check，校验通过才替换；使用跨平台安全文件替换。 |
| SQLite 恢复未检查其他连接 | 目标连接已断开，但另一条连接仍打开相同文件或路径别名。 | 扫描所有活动池的实际文件并拒绝覆盖；恢复与连接生命周期操作互斥。保护范围为本应用内连接，外部程序仍应关闭数据库后再恢复。 |
| 带注释的事务控制误判 | BEGIN/ROLLBACK 前有注释时，被错误包进软件管理的事务。 | 分类前剥离前导注释，保留脚本自管事务语义。 |
| Redis Escape 取消仍提交 | 单元格取消导致卸载，卸载清理把草稿发送给后端。 | 取消先标记草稿已处理，保留滚动卸载时正常保存行为。 |
| Redis string 编辑清除 TTL | 普通 SET 将临时 key 变成永久 key。 | 使用 SET KEEPTTL 保留服务端实时 TTL，不用读到的旧 TTL 重新续期。 |
| Redis 结果无 IPC 上限 | 大集合或大字符串转换后全部传给界面。 | 10,000 行及 8 MiB 序列化行数据预算；显示截断，禁止编辑不完整字符串。 |

Redis `KEEPTTL` 自 Redis 6.0 起支持，见 [Redis SET 文档](https://redis.io/docs/latest/commands/set/)。旧版服务器会返回不支持的命令错误，不会回退到丢 TTL 的 SET。

## 2026-10-18 续验：连接重载与整库备份

接续 Claude 的浏览器验收记录：上一阶段已验证 SQLite 备份，停在 PostgreSQL/MySQL 整库导出。本轮通过隔离 web bridge 的真实 Tauri command handler，在新建的临时数据库中执行导出和恢复，完成后清理临时库与进程。没有覆盖日常连接配置或原测试库。

| 发现的问题 | 本轮修复及验证 |
|---|---|
| WebView 重载后活动连接的版本丢失 | 状态接口返回活动池的真实版本，查询有超时；前端恢复连接状态及版本。异步保存/刷新结果受连接操作代际保护，避免覆盖后续连接或删除结果。 |
| PG/MySQL 导出失败破坏已有备份 | 同目录暂存、非空校验、成功后替换；实测无效数据库导出保留旧文件并清理暂存文件；单元测试覆盖客户端失败、取消、空输出和成功替换。 |
| MySQL 备份无法在原服务器恢复 | 真实恢复复现 GTID_PURGED 重叠错误；使用 `--loose-set-gtid-purged=OFF`，不修改恢复目标的全局 GTID 状态。这些备份用于应用数据恢复，不提供复制拓扑初始化。依据 [MySQL mysqldump 文档](https://dev.mysql.com/doc/refman/8.0/en/mysqldump.html)；`loose-` 用于不支持此选项的客户端兼容。 |
| MySQL 导出遗漏事件，二进制 SQL 含原始非文本字节 | 加入 `--events`、保留 `--routines`，并用 `--hex-blob` 导出；恢复后核对事件仍为禁用状态及 BLOB 精确字节。 |
| 整库导出对话框运行中无停止入口 | 增加停止导出，传入当前 operation id；后端结束前不能关闭。取消响应不污染下一次任务，实际工具错误继续显示原文。 |

## 2026-10-18 事件与序列管理

原清单中“事件/序列仅能浏览定义”的缺口已补上专用表单。对象树右键“管理对象”会携带连接、schema、类型和名称进入准确目标；对象工具页也可直接切换到事件或序列管理。表单按工作区宽度调整布局，窄面板将列表置于编辑区上方。

| 能力 | 行为与边界 |
|---|---|
| PostgreSQL 序列 | 创建、读取、原地 ALTER、显式 RESTART、RESTRICT 删除；类型/上下界/步长/缓存/循环可配置。整数全程为字符串，避免 JS 精度损失。普通保存不重置当前取号值，重启需另行确认，依赖关系阻止危险删除。schema/name 保持原值，超 63 UTF-8 字节的新标识符提前拒绝。identity 所属序列的普通修改已验证，类型及所有权限制仍由 PostgreSQL 执行。 |
| MySQL 事件 | 单次时间或简单整数周期（年/季度/月/周/日/时/分/秒）、起止时间、事件体、备注与完成后保留。新建默认禁用，启用和删除需确认；不修改全局 event_scheduler，OFF 时明确提示仍不会运行。原地 ALTER 保留原定义者、时区及 SQL_MODE；变更体仅支持单条 SQL，复杂逻辑用 CALL，未修改的历史 BEGIN/END 体不重写。组合周期及特殊定义者格式明确报错，可使用 SQL 编辑器处理。 |
| 名称与对象身份 | PG 重载函数以完整 identity 区分，刷新和替换仍指向所选签名；同名触发器按所属表区分。既有对象带首尾空格的合法名称不会被 trim 后写到其他对象；新建 schema 固定为外层选择的上下文。 |

事件命令使用单语句预处理协议，不因旧服务器不支持而退回多语句文本执行。较旧 MySQL 客户端/服务器组合仍需独立测试。本轮实测发现并修复了 MySQL 元数据返回的有符号长度、ENUM/SET/BLOB 与 Rust 字符串解码不匹配，以及周期单位 JSON 大小写契约不一致的问题。

实现语义参考 [PostgreSQL ALTER SEQUENCE](https://www.postgresql.org/docs/17/sql-altersequence.html)、[MySQL CREATE EVENT](https://dev.mysql.com/doc/refman/8.0/en/create-event.html) 和 [ALTER EVENT](https://dev.mysql.com/doc/refman/8.4/en/alter-event.html)。这些能力配置数据库原生对象，不等于新增了应用级定时任务调度器。

## 2026-10-18 同连接原生表复制

表右键“复制结构与数据”新增默认的原生模式，目标为同连接、同 schema 下尚不存在的新表。结构和数据由数据库直接复制，行数据不经过应用的 JSON 编码，因此无主键表、重复行以及超过 10,000 行或 16 MiB 的表也能复制。这不代表无限容量：数据库的空间、锁、类型和权限要求仍然适用，也不构成跨连接或跨库传输。

预览只读取结构并显示 SQL 与不会复制的对象，不扫描全表或承诺预览时的行数。执行时获取数据快照，重新核对源结构与目标是否存在；预览后新增或修改的数据可以包含在执行快照内，结构变化则要求重新预览。预览授权五分钟内有效且只能使用一次，连接变更使旧授权失效，只读连接不能执行复制。

| 数据库 | 复制方式与保留内容 | 明确边界 |
|---|---|---|
| SQLite | 在 `BEGIN IMMEDIATE` 事务中重建原始表定义、索引并执行 `INSERT SELECT`；保留主键、UNIQUE、CHECK、默认值、生成列定义、表达式/部分索引、STRICT、WITHOUT ROWID 和指向其他表的外键。生成列重新计算，AUTOINCREMENT 计数保留原高水位。普通隐藏 rowid 可访问时按原值复制，包含稀疏、负数和零。 | 仅 `main` 的普通表；拒绝视图、虚拟/影子表、内部表及自引用外键，不复制触发器。当 `rowid`、`_rowid_`、`oid` 三个别名都被声明列遮蔽且无 INTEGER PRIMARY KEY 别名时，会警告隐藏 rowid 可能改变。写事务期间其他写入需要等待。 |
| PostgreSQL | 在 repeatable-read 事务中锁定源表元数据，使用 `LIKE INCLUDING ALL` 和 `INSERT SELECT`。所属 serial 和 identity 序列为目标建立独立序列，按复制后的值、起点和步长方向对齐，不推进源序列；生成列重新计算。 | 仅普通堆表；拒绝分区、继承、行级安全、规则、类型绑定，以及共享、无归属或复杂序列默认值。源序列当前计数不直接照搬。外键、触发器、所有权、权限、表级存储选项、表空间、replica identity 和表注释不复制。 |
| MySQL | 仅普通 InnoDB 表；独立连接持有源表元数据锁，另一个连接用 `CREATE TABLE LIKE` 创建随机暂存表，以单次执行快照完成 `INSERT SELECT`，保留自增计数，最后原子 `RENAME TABLE` 发布。显式写入普通及 invisible 列，生成列重新计算。 | 源表结构变更需要等待元数据锁，普通数据写入可继续。外键、触发器、表级授权及 DATA DIRECTORY / INDEX DIRECTORY 不复制。DDL 无法回滚，失败或取消会清理本次拥有的暂存表，清理需要 `LOCK TABLES` 和 `DROP` 等权限；若权限、连接或清理失败，错误给出暂存表名供核对。建表请求已提交但响应丢失时，也会报告可能残留的暂存表，不盲目删除。已有目标不会被覆盖。 |

执行界面显示准备、建表、复制、完成或取消阶段及耗时，不显示估算百分比。取消需等待数据库中断和回滚或暂存表清理完成；进入最后的事务提交或原子改名阶段后不再接受取消。关闭对话框在运行期间禁用，界面卸载或请求被丢弃会请求取消，后端继续完成清理。

“可移植模式”仍可选择，继续使用原同步引擎的主键、类型、每侧 10,000 行和 16 MiB 限制及预览数据变更检查；其结构与数据分别提交，失败可能留下新建目标。上文早期验收记录中的复制规模限制描述对应这一模式。原生模式扩大了同连接复制的覆盖范围，没有改变跨连接同步和结构迁移的边界。

同时修复了复制/同步的连接切换竞态：执行使用先捕获、再核对代际的连接池；可移植模式在异步重预览后复核两侧连接及目标只读状态，创建目标后的第二次预览继续使用原连接。实际阻塞测试覆盖源/目标重连、只读状态变更及创建结构后的重连；拒绝数据写入时会明确报告已经创建的结构。
