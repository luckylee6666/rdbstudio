# 浏览器开发桥接

`pnpm dev:web` 会先构建和启动 Rust web bridge，确认监听就绪后再启动前端 Vite。浏览器里的 React 界面通过 bridge 调用项目真实的 Tauri command handler，因此可以在普通浏览器中调试需要后端、数据库连接或文件操作的界面。它适用于本机开发和测试，不是桌面应用替代品，也不是可部署的服务。

## 启动

先为 bridge 准备一个独立的数据目录，再从仓库根目录运行：

```sh
mkdir -p /tmp/rdbstudio-web-test-data
RDB_BRIDGE_DATA_DIR=/tmp/rdbstudio-web-test-data pnpm dev:web
```

脚本会启动 Vite（默认 `http://localhost:1420`）和监听回环地址的 bridge（默认 `http://127.0.0.1:1430`）。启动前检查 bridge 端口，若已占用则直接报错，不构建后端或启动 Vite，也不会终止已有服务。脚本为每次运行生成随机 token，并把相同 token 和 Vite 地址注入前端与 bridge。

退出或任一服务失败时，会清理本脚本启动的子进程树：macOS/Linux 使用独立进程组，Windows 使用对应 child PID 的 `taskkill /T`。桥接未就绪时不会提前启动前端。启动器测试为 `node --test scripts/dev-web.test.mjs`；Windows 进程管理目前有单元验证，仍需 Windows 实机验收。

**务必设置独立的 `RDB_BRIDGE_DATA_DIR`。** 未设置时，bridge 默认读写 `~/.rdbstudio`，也就是桌面应用使用的数据目录；其中保存连接配置、历史和片段。隔离目录可以避免开发时误改日常配置。只在隔离目录中添加专用测试连接，并为连接使用新的 ID；数据库密码由系统钥匙串管理，隔离目录不会隔离或清除已有钥匙串条目。

可选环境变量：

| 变量 | 默认值 | 用途 |
|---|---|---|
| `RDB_BRIDGE_DATA_DIR` | `~/.rdbstudio` | bridge 使用的连接、历史和片段目录。开发测试建议显式指定临时目录。 |
| `RDB_BRIDGE_PORT` | `1430` | bridge 的本机端口。修改时需确保前端配置使用同一端口；当前启动脚本会自动设置 Vite bridge 地址。 |
| `RDB_BRIDGE_ORIGINS` | `http://localhost:1420,http://127.0.0.1:1420` | 允许访问 bridge 的浏览器来源，逗号分隔。需要自定义 Vite 地址时应将来源限制为确切的本机开发地址。 |

bridge 只绑定 `127.0.0.1`，并校验 Host、Origin 和每次运行生成的 token。不要把它暴露到局域网或公网，也不要将 token 写入提交、截图或日志。

## 浏览器 shim 与限制

数据库命令会走 Rust command handler；需要原生窗口或插件的能力由浏览器端 shim 模拟：

- **文件对话框**使用 `window.prompt` 输入路径；它不会弹出系统文件选择器。读写仍由真实后端命令执行，因此输入的路径必须是运行 bridge 的本机可访问路径。
- **剪贴板**尝试调用浏览器 Clipboard API，并在当前页面内保留一个临时文本值作为回退。
- **更新器**的检查返回无更新结果，不会下载或安装更新。
- **窗口、事件和应用信息**只返回适合浏览器调试的简化结果；不模拟原生窗口状态、菜单、生命周期或系统事件。

因此，web bridge 可用于检查页面、真实命令调用、数据库行为和文件内容，但不能验收系统文件对话框、剪贴板权限、窗口行为、菜单快捷键、原生事件、打包签名或安装更新。需要这些能力时应在目标操作系统的 Tauri 桌面构建中单独验收。桌面 WebView 与普通浏览器也可能有不同的键盘、拖放和权限行为。

## 数据库测试

使用专用的本机测试库或可丢弃的 scratch database。连接恢复、整库导入等操作会修改目标数据库；执行前确认当前连接和目标环境。不要把生产库、含重要数据的库或共享环境用作测试目标。测试专用连接应只保存在独立数据目录中，完成后按需删除临时数据目录和测试库。

运行中的 bridge 会读取并持有该目录里的连接配置。不要在桥接进程运行时把目录切换到日常配置目录；如需更换数据目录，应先退出进程再重新启动。
